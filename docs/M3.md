# M3 — the sprite engine

`DESIGN.md` section 13: `blit_rle` plus per-buffer dirty rects; the chopper
moves cleanly with no flicker. This program does that and stops. It is not
the world scroller (M4), not joystick/flight (M5), and not the game.

M2 already put the flying set on screen with `blit_mask` and a single dirty
rect per buffer. M3 is the product-shaped path for the same picture:

1. **RLE sprites** and **`blit_rle_m8`**: each row is
   `{ skip_bytes, run_bytes, data[run_bytes] }*` terminated `0x00 0x00`.
   Opaque runs (`run >= 2`, both nibbles live) are `rep movsb`. A 1-byte run
   is a store or a mixed-nibble read-modify-write. Skip runs are transparent.
   There is no full-screen copy.
2. **A dirty list per back buffer**, one rect per blit (body, main rotor,
   tail — not a union of the three). Restore is from the scroll-invariant
   **band model**, with **even** byte widths (`fill_rect_m8` drops odd widths;
   that was the 9→8 trail).

The viewer keeps M2's 1-pixel bounce and pose cycle so the engine change is
judged as "same visual, cleaner path".

---

## Current status

**Accepted** on DOSBox and real PCjr. `build\m3.exe` is 22,528 bytes. Same
flying-set look as M2, on `blit_rle` and the list restore — judged by eye.

This program does **not** time dirty-rect or blit byte counts. Section 14
still lists that measurement as the way to replace the analysis working-set
line. Do not treat an emulator clock as hardware.

Quoted from `DESIGN.md` section 2 (real PCjr, `J:\GAMES\CHOPLIJR\M1.LOG`):
video `stosw` is **2803 ns/byte, 44.8 ms/screen**; RAM→video `movsw` is
**62.9 ms/screen**; RAM→video `movsb` (what `blit_rle` pays per opaque byte)
is **4515 ns/byte, 72.2 ms/screen**. A 16,000-byte fill or copy does not fit
a 50 ms 20 Hz frame. M3 only writes the opaque bytes of the sprites and the
word-padded dirty rects, never a full page.

Ground colour on this build is BROWN.

## Building

Same toolchain as [docs/M1.md](M1.md). From PowerShell:

```
. .\setenv.ps1
cmd /c "wmake NASM=lib\repos\nasm\nasm-3.02\nasm.exe"
```

That builds `build\m1.exe` through `build\m4.exe`. There is no
`wmake run-m3`; do not launch DOSBox from the makefile for this visual.

`GROUND=BROWN` (default) or `GROUND=PINK`. Clean first when changing it.

RLE data is generated by `python tools/build_sprites.py` into
`src/sprdata_rle.c` (packed M2 data stays in `src/sprdata.c` so `m2.exe` does
not carry the RLE set).

## Running (attended)

A human has to watch. The escape hatch is a keypress. Do not start an
emulator until someone is in front of it.

When someone is watching, from a PCjr DOSBox-X with `build\` mounted as `C:`
(the existing `conf/pcjr-dev.conf` / `conf/pcjr-128k.conf` mounts, after M1
returns to the prompt, or by typing at `C:`):

```
M3
```

`/force` on an emulator whose model byte is not `FDh`. `/batch` skips the
"press a key" pause. `/frames=N` changes the motion length (default 360 =
6 s at 60 Hz). `/bios` flips with `int 10h AX=0583h`. `/pa` `/pb` force pages
in 1–7 — do not overlay DOS-occupied pages on jrIDE.

On real hardware: the same `build\m3.exe`, JrConfig `DEVICE=JRCONFIG.SYS /V64 /L`,
pages 6 and 7.

### What a pass looks like

Text: memory / JrConfig / pages, then a key to enter mode 8 (unless
`/batch`). Then the chopper on the section 5 bands:

- Olive body (index 2), light-green topside (10), white rotors (15) on the
  side views; head-on frames have no rotors in this stub (same as M2).
- 1-pixel bounce left and right, so odd-X pre-shifts are exercised — not
  locked to byte columns.
- Pose cycle: 11 side tilts, then 5 head-on, 10 retraces per body frame.
- Skids toward the brown ground; sky/mountain/ground bands stay put.
- **No trail** either direction (word-padded restore; no leftover byte when
  moving left).
- **No flicker** between the two pages (per-buffer list: each page restores
  what *it* drew two frames ago).
- No venetian-blind bank error (even/odd scanlines in the two 8 KB banks).

A fail is crumbs behind the tail when moving left, a ghost of the previous
pose, a strobe between pages, or a chopper that only jumps two pixels at a
time.

Any key ends the motion early. After mode 3 is restored, the program prints
the pass-by-eye sentence and exits.

## What this does not do

- No camera, no mountain parallax, no barracks/base/fence (M4).
- No joystick, no tilt state machine (M5).
- No hostages, tanks, shots.
- No Zen-timer of dirty-rect or `blit_rle` byte counts.
- Playdate is out of scope.
